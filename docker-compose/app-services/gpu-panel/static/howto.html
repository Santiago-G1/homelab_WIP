The idea

The Tesla P100 has 16 GB and there are four things that want it: llama.cpp (LLMs, ~15.8 GB with a large model resident), Immich ML (CUDA, ~6.8 GB), Jellyfin NVENC (video transcoding) and ComfyUI (image generation, ~4-6 GB). Only one of the first three can own the card at a time, so the panel arbitrates: it watches what is really running and moves the others out of the way.
Two rules decide everything: llama.cpp comes first (while a model is loading or loaded, the other CUDA consumers step aside) and nothing stays on the card idle (each consumer has a release timer).

GPU modes

ModeWhat it doesWhen
LLM Unloads nothing by itself, stops Immich ML and moves Jellyfin to the iGPU (VAAPI), so the P100 belongs to llama.cpp. Chatting with the agent, coding models, long prompts.
Media Unloads the llama.cpp models, starts Immich ML and puts Jellyfin on NVENC (the P100). Smart search / face detection batches, 4K transcoding.
Shared Immich ML + Jellyfin NVENC without unloading the LLM. Only fits with a small model already loaded; useful for a quick ML job.
Image Unloads the LLM, stops Immich ML, moves Jellyfin to the iGPU and starts ComfyUI. Generating images. A diffusion model needs the whole card.
The highlighted button on the dashboard is derived from the real state every 5 s (which containers are up, where Jellyfin transcodes), not from the last click: if something changed outside the panel, the ring follows.

Auto-switch

Three timers, all measured from "the GPU has been idle this long" (utilisation 0 %). Set any of them to 0 to disable that one.
TimerWhat happens when it fires
Release the LLM (llama_idle_min) The llama.cpp models are unloaded from VRAM and Immich ML comes back, so smart search can run without you clicking anything.
Stop Immich ML (ml_idle_min) Immich ML is stopped when its own job queue is empty (it does not kill a running batch).
Release the P100 from ComfyUI (comfy_idle_min) ComfyUI is stopped once its queue is empty, so the next LLM request finds the card free. This is why Image mode does not need to be undone by hand.
The auto-switch is on by default. Turning it off leaves the modes purely manual (the panel still shows the state, it just stops acting on it).

ComfyUI

1. Press Image (ComfyUI) on the dashboard (or the ComfyUI card's Start button). The panel frees the card first, then starts the container.
2. Open comfy.<zona> — the URL is on the card. If it answers 502, the container is stopped: repeat step 1.
3. Drag a workflow from /mnt/data/image_models/workflows into the canvas, or build one: Unet Loader (GGUF/Advanced) for the unet, DualCLIPLoader (type sdxl) and VAELoader.
4. Generated images land in /mnt/data/comfyui_output; reference images go in /mnt/data/comfyui_workspace/ComfyUI/input.
SettingLeave it as
dequant_dtype / patch_dtype float16. float32 is not faster (the compute dtype is already fp16) and uses more scratch VRAM.
patch_on_deviceoff (required input since 2026).
Resolution / steps 1024² ≈ 70 s for 28 steps on this card. 768² ≈ 40 s, 512² ≈ 20 s.
ComfyUI-Manager Off. It can "update" torch, and torch 2.8+ no longer supports this GPU: the card disappears until the image is rebuilt.
The card is compute-bound at 1024² (100 % GPU, ~125 W, only ~4 GB of VRAM in use), so lower quants or offloading do not make it faster. Details: docs/comfyui.md in the lab repository.

Jellyfin

NVENC transcodes on the P100; VAAPI on the Intel iGPU (a different device, it costs the P100 nothing). When the LLM takes the card, Jellyfin is moved to VAAPI, never to CPU: transcoding stays hardware-accelerated.
Pick NVENC only when the card is free (Media mode). If playback starts stuttering right after a model load, check this value first: it should read vaapi.

llama.cpp logs

A tail of the llama-server systemd unit on the AI container (journald, read through the PVE host). What matters:
load time = … ms → how long the model took to come up (from the ZFS pool it is ~180 s for the 13.6 GB Q4; cached is much faster).
cudaMalloc failed: out of memory → something else held the VRAM. Check the consumers list: it should never happen in LLM/Image mode, which free the card first.
Xid or GPU has fallen off the bus → hardware/PCIe problem, the card needs a PVE reboot.

Power limit

The P100 is tuned to 165 W (application clock 1328 MHz): 99 % of its throughput at 92 % of the power. Below ~142 W the clock never reaches 1328 MHz, and above ~200 W nothing changes in real inference. Raising it is only worth it for a long sustained prefill; lowering it to 125 W gives ~91 % of the speed. The limit is applied by the PVE host (an unprivileged container cannot set it).

Automation

Everything the buttons do is an API call, with the panel token as a bearer: 
GET  /api/status
POST /api/mode/llm|media|balanced|image
POST /api/comfy/start|stop|restart
POST /api/auto            {"enabled":true,"llama_idle_min":60,"ml_idle_min":0,"comfy_idle_min":10}
POST /api/llama/unload
GET  /api/llama/logs?lines=200
POST /api/power           {"watts":165}
